## Second repair realization

`WHAT-E001-02` and `HOW-E001-02` first reconciled current target semantics. `PLAN-E001-02` then bounded implementation to Open authority and installed verification only; `READINESS-E001-02` found it ready.

The implementation introduced a small `OpenTransitionGuard` with two monotonic dimensions:

- an **intent generation** says which Open/New replacement intent is still current;
- a **content generation** says whether the current editable document changed after an Open ticket captured replacement authority.

The shell captures both in an immutable ticket and rechecks them immediately before candidate admission. DOCX admission is checked before current-session release. PDF candidate loading may finish asynchronously, but stale candidates cannot replace current state and are disposed. Existing PDF render freshness remains a separate downstream fence.

The verification-only startup path now returns actual success/failure. PDF open returns success only after the first render completes successfully. `--verify-close-after-open` suppresses modal error blocking and exits non-zero on failure. The Windows lifecycle script refreshes the process and requires `ExitCode == 0` before it accepts the installed PDF success claim.
