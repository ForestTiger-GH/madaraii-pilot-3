## Current implementation slice

Current Product already has candidate-first DOCX/PDF replacement and independent PDF-render freshness. The remaining gap is that `PdfSession.OpenAsync` can await without an Open-level ticket. During that wait a later New/Open or new edit can occur; late completion still admits the candidate. `OpenPathAsync` catches failures and returns no success value, while verification-close always closes afterward, so the installed lifecycle script cannot distinguish successful installed UI PDF admission/render from a caught failure.

## Semantic / realization delta

### S1 — explicit transition guard

Add a small internal, non-persistent shell-owned transition helper or equivalently compact mechanism containing:

- monotonic open-intent generation;
- monotonic document-content generation;
- immutable open ticket capturing both;
- `BeginOpen`, `SupersedeOpen`/new-document transition, `ContentChanged`, and current-ticket predicate semantics.

The helper owns no Product content and no background work. It exists to prevent duplicate ad-hoc generation logic and to allow deterministic semantic checks through existing `InternalsVisibleTo("MiniDoc.Checks")`.

**Checkpoint:** deterministic tests prove a later open supersedes an earlier ticket, a content change invalidates the captured ticket, and an untouched current ticket remains admissible.

### S2 — shell admission integration

Integrate the guard into the existing `MainWindow` lifecycle:

- a user Open command establishes a new intent before any long candidate operation, so a later Open/New can stale an earlier pending attempt;
- New supersedes pending Open before establishing the new document;
- material edits/format changes advance document-content generation through the existing dirty-marking path;
- startup/programmatic open obtains the same governed ticket semantics;
- DOCX/PDF candidate admission checks the ticket immediately before current-session replacement;
- a stale PDF candidate is disposed;
- stale attempt failures/status changes are suppressed when a newer intent owns the UI;
- if intent is still current but content generation changed, preserve current document/dirty state and expose a bounded cancellation message rather than replacing it.

Do not disable the whole window, introduce a global scheduler, add autosave, or persist operation state.

**Checkpoint:** source/state audit plus semantic guard checks establish later-intent and post-prompt-edit authority. Existing first-Jester candidate-first and render-freshness semantics remain intact.

### S3 — explicit open/render success contract

Change only the internal startup/open call chain needed for evidence:

- `OpenPathAsync` / PDF open path return success/failure;
- PDF success is true only after candidate admission and successful first-page render for the still-current request;
- interactive callers may ignore the returned bool after existing user-visible error handling;
- verification startup observes the bool; in `--verify-close-after-open` mode a false open/render result yields non-zero process exit, while success closes through the normal window path and exits zero.

No persistent marker file, hidden cache, telemetry or user-visible command is created.

**Checkpoint:** ordinary successful verification-close on fixture returns zero; failure path is statically/semantically bound to non-zero.

### S4 — Windows oracle strengthening

Update `scripts/verify-windows.ps1` after `Wait-Process` to refresh/read the installed process exit code and fail unless it is zero. Retain all existing process-termination, owner-state, user-sentinel and uninstall-residue assertions.

**Checkpoint:** Windows CI must pass on the exact candidate; its successful run now supports installed shell PDF admission + first render + normal close, not merely attempted path + process exit.

### S5 — fan-in and candidate freeze

Run existing semantic checks/build/publish/package plus strengthened Windows lifecycle verification. Freeze one exact candidate commit/configuration for MADARAII-33. Do not alter Product criteria after observation.
